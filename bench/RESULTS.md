本文件由 `bench/make_report.py` 从 `bench/results.json` 自动生成。**报告里的每个数字都来自原始输出，未经手工填写。**

- 运行时间：`2026-10-16T14:39:27.770258+00:00`

- 重复次数：**1**（见「局限」一节）
- 实际花费：**0.026159 元** / 18 次调用

## 1. 做了什么

让大模型做 finverify 做的**同一件事**（从三张财务报表文本中抽取 12 个标准科目），然后回答三个问题：

1. **抽得准不准** —— 与 finverify 确定性抽取的 ground truth 逐项对账，区分「照抄正确」「串行取错行」「凭空捏造」「抽不到」。
2. **它给的数字自洽吗** —— 把 LLM 输出的数字直接送进 finverify 自己的 `ValidationEngine`，看会计恒等式是否成立。**这里刻意复用产品代码而非重写恒等式**：评测逻辑与被评测对象共用一套判定，否则结论不可信。
3. **它算得对吗** —— 要求模型基于同一份文本计算三个派生指标（资产负债率、销售净利率、经营现金流倍数），与确定性计算结果比对。

样本包含 3 份合成年报，其中 2 份注入了勾稽错误：

- **干净样本（勾稽成立）**
- **注入 A：权益多记 5,000 万**
- **注入 B：所得税少记 1,200 万**

> 注入的错误数字在文本里与正常数字**完全一致**，模型没有任何线索可以察觉——除非它自己给出的这组数字自相矛盾。

## 3. 结论

### 3.1 「LLM 会把财报数字抽错」——在本实验的难度下不成立

在格式规整的三表文本上，3 个模型合计 108 个指标次，抽取准确 108 次（100%），**凭空捏造 0 次**，派生指标计算也全部正确。

所以「换个更强的模型就能解决财报抽取」这个论断，在这个受控条件下是成立的。**如果只做到这一步，finverify 的价值主张是不成立的** ——这也是为什么下面这一节才是重点。

### 3.2 真正的风险不是「抽错」，是「忠实地抽错」

在注入了勾稽错误的样本上，模型的抽取准确率依然是 **12/12 满分** —— 因为它完美地复制了原文里那个被篡改的数字。

从任何只看「抽取准确率」的评测体系看，这个模型的输出都是满分通过的。但它交出来的那组数字**内部自相矛盾**：

| 样本 | 注入额 | 恒等式实测差异 | 跨模型一致性 |
|---|---:|---:|---|
| 注入 A：权益多记 5,000 万 | -50,000,000 | -50,000,000.00 | ✅ 3/3 个模型均恰好吻合 |
| 注入 B：所得税少记 1,200 万 | -12,000,000 | -12,000,000.00 | ✅ 3/3 个模型均恰好吻合 |

**结论：抽取准确率回答的是「你抄对了吗」，而业务真正要问的是「你抄的这组数字说得通吗」。这是两个不同的问题。**

这也是 finverify 三态设计的用武之地：所有模型在干净样本上都是 0 命中（零误报），在注入样本上差异额精确等于注入额（零漏报）。

### 3.3 成本对照

| 模型 | 输入 token | 输出 token | 单次成本 | 抽取准确率 |
|---|---:|---:|---:|---:|
| `deepseek-chat` | 415 | 175 | 0.00223 | 36/36 |
| `deepseek-reasoner` | 441 | 670 | 0.00178 | 36/36 |
| `qwen-plus` | 524 | 235 | 0.00089 | 36/36 |

本次评测**全部花费 0.0262 元**。最贵的模型与最便宜的模型在这个任务上准确率相同 —— **校验层带来的成本远低于模型升级带来的成本，真正该花钱的地方是校验，不是换一个更大的模型。**

## 4. 局限（必须写清楚，否则这份结论会被高估）

1. **样本量极小**：9 次运行，每格仅 1 次。`docs/EVALUATION.md` 要求每组 3 次取中位数，本次为控制成本未做。单次采样无法给出方差，**不足以支撑统计显著性结论**。
2. **样本是合成的**：格式规整、无合并单元格、无扫描件 OCR 噪声、无脚注与附注交叉引用。真实年报的解析难度远高于此，**本实验大概率低估了 LLM 的失败率**。
3. **模型覆盖有限**：仅 3 个模型，且全部为国产/开源阵营，没有闭源旗舰（GPT / Claude 等）作为对照。
4. **只测了三张表的 12 个科目**，没有覆盖附注、关联方交易、或有表外影响的复杂科目。

> 这份结果的正确用法是**证明方法可行、给出可复现的基线**，而不是宣称「finverify 解决了财报幻觉问题」。把它写成结论还太早 —— 需要的是 50 份真实年报，那是下一步的事。

## 5. 复现

```bash
export DEEPSEEK_API_KEY=...      # 或放到 key.txt
export DASHSCOPE_API_KEY=...

# 预算硬上限写死在代码里，超限立即终止，不会超支
python bench/run_bench.py --budget 0.50 --repeats 3
python bench/make_report.py      # 从 results.json 重新生成本文件
```

`bench/llm_client.py` 里的 `Budget` 在**每次调用前**按预估费用扣款，超过上限的 85% 直接抛错终止 —— 费用约束由代码强制，不靠自觉。

`results.json` 保留了**每个模型的原始回复全文**，不做任何筛选。
