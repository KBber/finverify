# Benchmark 设计 —— 财务数字幻觉率

> 这个文档是 finverify 的核心差异化资产。
> 工具谁都能写，**评测方法论**才是护城河。

---

## 1. 要回答的问题

大模型在财报上抽取财务指标时，错的到底有多少？错在哪？

现有财经 benchmark（如 FinQA、ConvFinQA）测的是**问答准确率**，
但一个模型可以答对结论、却在中间用错了数字而无人察觉。

**finverify 测的是一个更底层的东西：数字本身是否正确、是否有出处。**

---

## 2. 三个指标

### 2.1 抽取准确率（Extraction F1）

| 指标 | 定义 |
|---|---|
| `exact_match` | 数值完全相等（归一到"元"后） |
| `tolerance_match` | 相对误差 < 1%（吸收四舍五入） |
| `FP` | 抽出了不存在的指标 |
| `FN` | 漏抽了存在的指标 |

```
F1 = 2 * precision * recall / (precision + recall)
```

### 2.2 溯源率（Provenance Rate）

```
provenance_rate = |带有效 EvidenceSpan 的抽取| / |全部抽取|
```

低于 `PARAPHRASE` 等级的证据不计入分子。

**这是本项目的核心指标** —— 工具好不好，看它能否给出可验证的出处。

### 2.3 勾稽检出率（Identity Detection Rate）

```
detection_rate = |被恒等式抓出的幻觉| / |注入的幻觉总数|
false_alarm    = |被误判为 FAIL 的正确数据| / |全部正确数据|
```

做法是**注入式对抗测试**：

```
在年报中人为篡改某个数字 → 看引擎能否抓到
```

| 注入方式 | 预期 |
|---|---|
| 篡改资产负债表单项 | ✅ 必然抓到（恒等式破） |
| 篡改两项使其仍然平衡 | ⚠️ 抓不到 —— 这正是要诚实标注的能力边界 |
| 篡改无勾稽关系的独立项 | ❌ 抓不到 —— 需要跨表交叉校验兜底 |

> **主动标注"抓不到什么"，比吹"什么都能抓"可信得多。**
> 这也是 README 里坚持三态而非二态的原因。

## 3. 数据集构建

### 3.1 来源

- **A 股年报**：巨潮资讯网公开披露文件（cninfo）
- **美股 10-K**：SEC EDGAR
- 只用**公开可下载**的文件，规避任何数据合规问题

### 3.2 规模

| 层级 | 数量 | 用途 |
|---|---|---|
| 样本量 | 50 份年报 | 主评测集 |
| 指标/份 | 30–60 个标准科目 | 抽取评测 |
| 勾稽对 | 每份 3 组 | 恒等式评测 |
| 注入幻觉 | 150 个（25 份 × 6 种） | 检出率评测 |

### 3.3 分层抽样

避免样本偏差：

- **行业分层**：金融 / 制造 / 科技 / 地产 / 公用事业
- **规模分层**：大盘 / 中盘 / 小盘
- **格式分层**：表格密集型 / 图文混排型 / 纯文本型

> 表格密集型年报是解析最难的部分，必须单独成一个分层，
> 否则 benchmark 会被"多数简单样本"稀释成好看的假象。

## 4. 多模型对比

目标对比矩阵：

| 模型 | 类型 |
|---|---|
| GPT-4o / o 系列 | 闭源旗舰 |
| DeepSeek-V3 / R1 | 闭源开源双模 |
| Qwen2.5 / Qwen3 | 国产开源 |
| MiniMax / 智谱 | 国产闭源 |
| Qwen2.5-7B-Instruct | 小参数开源（本地可跑） |

**产出物**：

1. 抽取 F1 排行榜
2. 溯源率对比 —— 预计闭源模型更高，但需实测
3. 勾稽检出率对比 —— 验证"模型越强幻觉越少"是否成立
4. **成本-准确率曲线** —— 小模型 + 校验层 是否优于 大模型裸跑

> 第 4 点是最有说服力的结论：
> **如果 finverify 校验层能让 7B 模型达到 4o 的可信度，
> 那它就不只是评测工具，而是降本方案。**

---

## 5. 复现性要求

- 固定模型版本（记录 `model_id` + 发布日期）
- 固定 temperature（建议 0，但仍记录实际值）
- 每组至少 3 次取中位数，报告方差
- 发布原始输出，禁止"只发布最优结果"
- 提供一键复现脚本与原始数据 hash

## 6. 与 MiniMax「垂类场景 benchmark 构建」岗位的对应

| JD 要求 | 本项目对应 |
|---|---|
| 参与垂类场景 benchmark 构建 | 财报垂类评测集 |
| 赋能测试场景的 Agent 设计和建设 | 校验层本身就是 Agent |
| 熟悉 LLM / Agent 生态 | 评测方法论 |
| 创新性解决实际痛点 | 数字幻觉是真实痛点 |
| Hands-on，快速迭代 | 全栈自建，无依赖 |
